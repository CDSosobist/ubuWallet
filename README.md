# Шкатулка

**Локальный сейф паролей и данных банковских карт для Ubuntu.**
Нативное приложение на GTK 4 / libadwaita, без облака, аккаунта и сетевых запросов.

<p align="center">
  <img src="shkatulka/resources/io.github.shkatulka.Shkatulka.svg" width="120" alt="Иконка Шкатулки">
</p>

> **Статус:** 1.1.0. Был внешний обзор кода, но формальный независимый
> аудит/пентест не проводился. Для критичных данных изучите
> [модель угроз](SECURITY.md) и сделайте собственные резервные копии.

## Возможности

- Пароли: название, логин, пароль, сайт, заметки, теги, избранное.
- Банковские карты: владелец, номер, срок действия, платёжная система, заметки.
- Поиск по названию, логину, сайту, тегам и последним 4 цифрам карты.
- Генератор паролей на `secrets` (OS CSPRNG), длина 8–128 символов.
- Маскирование паролей и номеров карт, показ по кнопке-«глазу» с повторным скрытием и автоскрытием через 30 секунд.
- Копирование в буфер обмена с автоматической очисткой через 5–60 секунд.
- Автоблокировка при неактивности (1–60 минут), при блокировке экрана GNOME и перед сном системы; ручная блокировка `Ctrl+L`.
- Смена мастер-пароля с полной перешифровкой сейфа.
- Резервные копии: зашифрованный файл и импорт с подтверждением.
- Никакой телеметрии, сетевых вызовов и «восстановления через e-mail».

## Безопасность в двух словах

| Слой | Реализация |
|---|---|
| Ключ из мастер-пароля | **Argon2id**: 64 МиБ, 3 прохода, 4 линии, соль 128 бит (RFC 9106) |
| Шифрование | **AES-256-GCM**, случайный 96-битный nonce на каждое сохранение |
| Целостность | Тег GCM + заголовок файла как Associated Data |
| Файл сейфа | Атомарная запись, каталог `0700`, файл `0600`, fsync |
| Память | Ключ в `bytearray`, обнуление при блокировке; временные копии Python/OpenSSL — см. ограничения |
| Мастер-пароль | Не хранится, не логируется, не передаётся; минимум 15 символов |
| Карты | Проверка Луна, маска «•••• 1234», **CVV/CVC и PIN не хранятся** |
| Блокировка | Автоблокировка по бездействию, блокировка экрана GNOME/сна, ручная, очистка буфера обмена |
| Локальность | Интерфейс не содержит сетевого кода; данные не покидают компьютер |
| Процесс | `umask 077`, отключение core dump и ptrace (`PR_SET_DUMPABLE=0`) |
| Журналирование | пользовательские строки без Pango markup; ошибки без секретов |

Подробности, модель угроз и ограничения — в [SECURITY.md](SECURITY.md).

## Установка

Требуется Ubuntu 24.04+ (GNOME) или другой дистрибутив с GTK 4.14+,
libadwaita 1.5+, Python 3.11+. Проверено на Ubuntu 26.04 с GTK 4.22 и
libadwaita 1.9.

```bash
sudo apt install python3-gi gir1.2-gtk-4.0 gir1.2-adw-1 \
                 python3-cryptography python3-argon2
```

Установка в домашний каталог (без `sudo`):

```bash
./install.sh
```

Запуск:

```bash
~/.local/bin/shkatulka
```

Приложение также появится в меню GNOME как **«Шкатулка»**. Код устанавливается
в `~/.local/lib/shkatulka/app`, данные — отдельно, в
`~/.local/share/shkatulka`. Иконка и `.desktop` файл — в `~/.local/share`.

Удалить программу, **не трогая сейф**:

```bash
./uninstall.sh
```

Скрипт удаляет только код, ярлык и иконку. Каталог с `vault.shk` не удаляется.

### Запуск без установки

```bash
./run.sh
```

## Первый запуск

1. Придумайте мастер-пароль длиной **не менее 15 символов**. Лучше — длинную
   фразу из нескольких слов. Требований к заглавным буквам и символам нет.
2. Подтвердите, что понимаете: **пароль восстановить невозможно**.
3. Добавьте пароль или карту кнопкой `+`.
4. Скопируйте нужное значение — буфер обмена очистится автоматически.

Сейф создаётся здесь:

```
${XDG_DATA_HOME:-~/.local/share}/shkatulka/vault.shk
```

Файл `.lock` рядом защищает от одновременной записи двумя экземплярами.
При импорте рядом может появиться зашифрованная копия `vault.shk.bak-…`;
других файлов с данными приложение не создаёт.

## Резервные копии

**Настройки → Резервные копии → Экспортировать зашифрованную копию.**

Копия — это тот же зашифрованный файл с тем же мастер-паролем. Храните её на
отдельном носителе. Импорт заменяет текущий сейф после подтверждения и ввода
пароля копии.

Если текущий мастер-пароль утрачен, на экране блокировки (или при первом
запуске) нажмите **«Импортировать копию»** и введите пароль резервной копии.
Файл сейфа будет заменён; после этого сейф нужно разблокировать паролем копии.
При импорте данные перешифровываются с новой солью и текущим профилем
Argon2id, поэтому старая или ослабленная копия не понижает защиту.

Перед заменой текущий файл автоматически сохраняется рядом как
`vault.shk.bak-<UTC-время>` (в том же каталоге, права `0600`). Это
зашифрованная копия, её можно открыть прежним мастер-паролем.

> Старые копии после смены мастер-пароля открываются только старым паролем.
> После смены пароля создайте новую копию.

## Если мастер-пароль не подходит

- Проверьте регистр, раскладку клавиатуры и Caps Lock. Пароль учитывает
  пробелы и не нормализуется; нажмите иконку «глаз» в поле, чтобы проверить
  ввод.
- В версии 1.0.0 был дефект ввода мастер-пароля: поле могло сохранить не то,
  что вы набирали. Исправление в 1.0.1 не может восстановить уже сохранённый
  пароль — он хранится только как криптографический ключ.
- Проверить пароль без GUI можно так (ввод не отображается и не попадает в
  историю shell):

```bash
python3 - <<'PY'
from getpass import getpass
from shkatulka.vault import VaultStore, VaultSession
password = getpass("Мастер-пароль: ")
session = VaultSession.unlock(VaultStore(), password)
print("OK, записей:", len(session.vault.items))
session.lock()
PY
```

- Если сейф тестовый и ценных данных нет, закройте приложение и переместите
  файл `~/.local/share/shkatulka/vault.shk` в другую папку — после этого
  приложение создаст новый сейф. Не удаляйте старый файл, если не уверены:
  он зашифрован и может пригодиться.
- Если данные важны, восстановить их можно только из резервной копии с
  известным паролем. Сброса пароля не существует.

## Где хранятся данные и что видно на диске

Файл сейфа — компактный JSON-конверт:

```json
{
  "format": "shkatulka-vault",
  "version": 1,
  "vault_id": "UUID",
  "kdf": {"name": "argon2id", "salt": "...", "time_cost": 3,
           "memory_kib": 65536, "parallelism": 4, "key_len": 32},
  "cipher": {"name": "aes-256-gcm", "nonce": "..."},
  "ciphertext": "..."
}
```

В открытом виде видны только версия формата, случайный идентификатор сейфа и
параметры KDF. Количество записей, заголовки, логины, номера карт и заметки
находятся внутри шифротекста. Заголовок аутентифицируется как AAD: подмена
nonce, соли или параметров KDF приводит к отказу расшифровки.

## Политика мастер-пароля

Приложение следует практикам NIST SP 800-63B-4 для локального однофакторного
доступа:

- минимум 15 символов (максимум 1024 байта);
- никаких обязательных заглавных букв, цифр и спецсимволов;
- проверка по небольшому списку распространённых паролей и тривиальных
  повторов/последовательностей;
- нет принудительной периодической смены пароля;
- пароль не обрезается и не нормализуется — учитывается каждый символ.

Пароли внутри записей могут быть любыми; для них показывается оценка стойкости
и предлагается генератор.

## Соответствие стандартам и практикам

Это не сертификация. Ниже — какие требования и практики учтены.

| Источник | Что учтено |
|---|---|
| RFC 9106 | Argon2id, профиль 64 МиБ / 3 / 4, соль 128 бит |
| NIST SP 800-38D | AES-256-GCM, 96-битный nonce, AAD |
| NIST SP 800-63B-4 | длина, blocklist, отказ от composition rules и rotation |
| OWASP ASVS 5.0 | аутентификация, криптография, защита данных, обработка ошибок |
| OWASP Password Storage Cheat Sheet | Argon2id с параметрами выше минимума |
| PCI DSS 4.0.1 | отказ от хранения CVV/CVC/PIN, маскирование PAN |
| CWE-312 / CWE-798 | нет открытого текста на диске и встроенных секретов |
| CWE-316 | частично: ключ обнуляется, но Python-строки не стираются гарантированно |
| FIPS 140-3 | **не сертифицировано**; приложение не работает в FIPS-режиме |

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Покрыты: KDF/шифрование, подмена заголовка и шифротекста, ограничения KDF,
UTF-8 пароли, модели и валидация PAN/сроков/тегов, bidi-спуфинг, политика
пароля, генератор, throttle, создание/сохранение/разблокировка, смена пароля,
параллельные save/change-password, права файлов, символические ссылки,
атомарная запись, лимитированное чтение бэкапов (FIFO/размер), экспорт/импорт,
резервная копия перед импортом и повреждённые payload.

UI проверялся вложенным X-сервером (Xephyr) с программным рендерингом:
создание сейфа, добавление и редактирование записей, поиск, блокировка,
разблокировка, настройки, генератор, смена пароля, переключение показа
пароля/номера карты, редактирование PAN и специальные символы `& < >` в данных.

## Окружение и модель угроз

- **Wayland** (текущая сессия): ввод и экран изолированы композитором;
  приложение не может читать ввод других окон.
- **X11**: любое приложение того же пользователя технически может читать
  нажатия клавиш и содержимое экрана. Для сейфа предпочтителен Wayland;
  это ограничение ОС, а не приложения.
- **Процессы того же пользователя** не входят в модель угроз как полноценный
  противник. `PR_SET_DUMPABLE=0` и `python3 -P` снижают конкретные векторы
  (ptrace, подмена модулей из текущего каталога), но вредоносный процесс с
  доступом к домашнему каталогу всё равно может атаковать приложение.
- **Физический доступ к разблокированной сессии** и вредоносное ПО/root не
  рассматриваются как защищаемые сценарии.

## Ограничения

- Приложение не защищает от вредоносного ПО, root, кейлоггера, захвата экрана,
  истории буфера обмена и физического доступа к **уже разблокированному**
  компьютеру.
- Python не позволяет гарантированно затереть все копии строк в памяти;
  обнуление ключа — best-effort защита.
- Нет защиты от отката к старой копии файла: локальный атакующий с правом
  записи может подменить сейф на ранее сохранённый валидный.
- Нет аппаратного ключа, TPM, биометрии и интеграции с системным keyring.
- Размер файла и время изменения видны снаружи и могут косвенно указывать на
  количество записей и время работы с сейфом.
- Атомарная замена и удаление не гарантируют затирание старых блоков на
  носителе; используйте полношисковое шифрование.
- **Формальный независимый аудит/пентест не проводился.**

Рекомендуется включать полношисковое шифрование Ubuntu, блокировку экрана,
обновления системы и хранить резервные копии офлайн.
